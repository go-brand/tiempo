# Roadmap decision audit

8 October 2026 · `@gobrand/tiempo` 3.0.1 · source commit `6219c0a`

Purpose: challenge every recommendation against Tiempo's ambition to be a familiar, flexible utility library for Temporal that people and AI agents learn quickly. This is a review of the backlog, not an implementation report. The [revised roadmap](../roadmap.md) retains all 43 identifiers for traceability.

## Decision standard

Prefer a change when it fixes a reproducible contract violation, makes related calls predictably consistent, or removes repeated work in a demonstrated task. Count migration, ambiguity, maintenance, bundle cost, and documentation burden against the benefit. More exports and stricter types are neither automatically good nor automatically bad. A useful thin wrapper can be worth shipping.

Three passes informed the decisions:

1. **Reality:** separate reproducible failures, documented limitations, inaccurate documentation, and product hypotheses.
2. **Counterexamples:** challenge proposed rules with existing UTC workflows, repeated hours, date-only values, future local appointments, arbitrary timezone strings, and concise native Temporal alternatives.
3. **Delivery:** remove unnecessary major-version dependencies, check each item's acceptance criterion, and distinguish committed fixes from gated experiments.

“Keep” means the work is justified; “revise” narrows or changes the proposal; “defer” means no implementation commitment until the stated evidence exists. No library implementation was changed during this decision audit.

## Additional evidence from this pass

These checks supplement the implementation review. They are author-run tests and observations, not an independent AI-user study.

- **Incorrect first example:** `2025-03-09T07:00:00Z` in New York is `03:00-04:00`. Adding one calendar day produces “Monday at 3:00 AM” and `2025-03-10T07:00:00Z`. The README says 2 AM and 06:00Z; the UTC-storage reference also shows the wrong local hour. Relevant sources: `README.md`, `skills/tiempo/references/best-practices/utc-storage.md`. Covered by **34**.
- **Confirmed type inconsistency:** nine small TypeScript consumer cases were compiled with no unrelated diagnostics. PlainDate `addDays`, generic `format`, and generic `isBefore` fail; `addQuarters`, `formatPlainDate`, and `isPlainDateBefore` succeed. Numeric `toInstant(0)`, `IANATimezone = 'UTC'`, and an arbitrary `Timezone` string compile. These are observations of current signatures, not proof every proposed overload should be added. Covered by **14/16/19/30/33/34**.
- **Misleading generated claims:** `scripts/generate-docs.ts` says IANATimezone excludes UTC, but the generated type ends in `string & {}`. `scripts/generate-capability-matrix.ts` flattens parameter/return information and misses numeric inputs. Fix generators and manual owners, then regenerate; editing generated copies alone will not last. Covered by **33/34**.
- **Equality counterexample:** New York `2025-11-02T01:30-04:00` and `01:30-05:00` compare equal with current `isSameHour` and `isSameNanosecond`, while exact difference is `3_600_000_000_000n`. Preserve the distinction explicitly rather than declaring all equality helpers interchangeable. Covered by **15/18**.
- **Local input is a separate task:** `toZonedTime('2025-03-09T10:00:00', 'America/New_York')` throws because the string lacks an offset. The existing recipe uses `date.toPlainDateTime(time).toZonedDateTime(zone)`. Teach it; do not silently reinterpret an established parser. Covered by **20/35/42**.
- **Discovery infrastructure is already present:** deployed `/llms.txt`, `/docs/ai-resources`, `/.well-known/agent-skills/index.json`, the skill Markdown, and `/.well-known/markdown/docs/conversion/to-instant.md` returned HTTP 200. Requesting the conversion page with `Accept: text/markdown` returned Markdown with `Vary: Accept` and discovery links. This verifies those routes at audit time, not all documentation contents. Covered by **34/35**.

The [llms.txt proposal](https://llmstxt.org/) supports concise context and links to detailed Markdown. That supports improving Tiempo's existing learning path; it does not establish universal agent adoption or search/recommendation ranking. The distinction between local date-time and a zoned moment follows [Temporal's PlainDateTime documentation](https://tc39.es/proposal-temporal/docs/plaindatetime.html).

## What was removed from the recommendation

- An automatic breaking ban on Instant calendar operations and UTC formatting.
- Automatically changing `isSameNanosecond` to timeline equality.
- Making every correctness/additive improvement wait for a full v4 contract.
- Treating native-first runtime selection, every missing feature family, or broad framework/tooling work as inevitable progress.
- Requiring a wrapper to save lines before it can improve familiarity or consistency.
- Treating more documentation, discoverability endpoints, or “AI-friendly” claims as evidence of successful learning.

## Remaining uncertainty and completion boundary

All 43 original items have a disposition. Verified failures and new documentation errors have owners in the revised backlog. Breaking designs and feature candidates have explicit gates. The [learnability evaluation](2026-10-08-ai-learnability-evaluation.md) specifies how to test the remaining product hypotheses.

No cold-learner benchmark has been run, no implementation fixes have been shipped, and no ranking outcome has been demonstrated. Those are subsequent work. This audit establishes a more defensible list of what to fix, what to try, and what not to assume.
